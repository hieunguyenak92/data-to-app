## Start with a job

After [installing the skill](docs/INSTALL.md), ask your agent:

> Use Data to App on `./exports`. Build a local inventory tool with stock search, a low-stock view, editable reorder levels and notes. Preserve those edits when I import the next export, and show me changes that need a decision. Launch the app and verify the main actions.

The skill guides the agent through inspecting the files, choosing identities and operations, building the app and exercising it. You describe the work; the agent handles the technical model. A material ambiguity in a key, unit or business rule may need one clear answer from you.

Good starting jobs include inventory and order exports, contact lists that need ongoing corrections, and project or service records that arrive in recurring files. The first version focuses on local, individually keyed tables and their requested workflows.

## Built for the second import

| Capability | What it gives you |
| --- | --- |
| **Identity-aware profiling** | Evidence about candidate keys, missing values, duplicates and identifiers with leading zeros. |
| **Join preflight** | A check for unmatched keys and row multiplication before the agent combines data. |
| **Three-way reconciliation** | Separate source, local and incoming values, with field-level decisions for conflicting edits. |
| **Import preview** | Review additions, updates, missing records and conflicts before applying a snapshot. |
| **An operational interface** | Search, configured views, permitted editing, conflict resolution, history and CSV export. |
| **Portable application source** | A generated Python/SQLite app with local assets that runs independently of the installed skill. |

These mechanisms give the agent concrete evidence to work with. A unique column is a key candidate, not proof of business identity. A successful join is not proof that its totals mean what you intended. The skill uses the tools and your objective to make those decisions explicit.

## Run the inventory workspace

Requires **Python 3.10+**. CSV ingestion and the generated runtime use the standard library. The bundled data is synthetic.

```bash
git clone https://github.com/hieunguyenak92/data-to-app.git
cd data-to-app
python3 skills/data-to-app/scripts/dta.py demo --out ./inventory-app
python3 inventory-app/app.py --port 8765
```

Open **http://127.0.0.1:8765**. Search for a product, open its editor, change a permitted field and export the result. The workspace stores its state in its own SQLite database. Restarting the app keeps that state.

To preview the next products snapshot, run this in another terminal from the repository directory:

```bash
python3 skills/data-to-app/scripts/dta.py import ./inventory-app --table products --file skills/data-to-app/assets/examples/inventory/next/products.csv
```

Add `--apply` to apply it, or use the app's import preview and confirmation. Try changing a field that also changes in the incoming file to see conflict resolution in action.

An import represents a **complete snapshot of one table**. Absent records are marked missing and retained. A partial export will therefore mark its omitted records missing. Schema changes and ambiguous conflicting keys are rejected before mutation.

## Bring your own files

A CSV is a text table; an XLSX is an Excel workbook. For XLSX input, install the optional reader in the Python environment used to run the toolkit:

```bash
python3 -m pip install openpyxl==3.1.5 defusedxml==0.7.1 et-xmlfile==2.0.0
```

Input bounds are **10 MiB per file, 50,000 rows per table, 200 columns and 1,000,000 cells**. XLSX uses the first worksheet by default and warns when others are present. Formulas are not recalculated.

Begin with the skill prompt above, or inspect files directly:

```bash
python3 skills/data-to-app/scripts/dta.py inspect ./exports
```

The agent can use the profile to configure a model and build your workspace. [Installation and CLI details](docs/INSTALL.md) explain the technical path in English.

## Export, ownership and boundaries

CSV export contains effective active values, including accepted local edits. Spreadsheet-formula guarding may prefix an apostrophe to risky exported cells; stored values remain unchanged. Missing records are retained locally rather than silently removed.

The generated runtime binds to `127.0.0.1`, serves local assets and requires no hosted service for its core operations. Your AI host's file-access and data policies still apply while the agent builds the app. Generated databases, inputs and exports may contain sensitive information. [Privacy details](docs/PRIVACY.md).

This release is a local workspace, without multi-user authentication or a cloud-deployment guarantee. It does not execute spreadsheet formulas, infer every business rule, support arbitrary schema migration or promise universal data recovery. Inspect important results before using them operationally.
