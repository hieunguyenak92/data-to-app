## 実際の仕事から始める

[スキルを導入](docs/INSTALL.md)したら、エージェントに依頼します。

> Data to Appで`./exports`を処理してください。在庫検索、発注基準を下回る商品のビュー、発注基準とメモの編集ができるローカル在庫ツールを作ってください。次のファイルを取り込むときも編集を保持し、判断が必要な変更を表示してください。アプリを起動して主な操作を確認してください。

スキルはファイルの検査、レコードの識別方法と操作の選択、アプリの構築、実際の動作確認へとエージェントを導きます。利用者は仕事を説明し、技術的なモデルはエージェントが組み立てます。キー、単位、業務ルールに重要な曖昧さがある場合は、利用者の明確な回答が必要になることがあります。

在庫・注文のエクスポート、継続的に修正する連絡先、定期ファイルで更新される案件・サービス記録に適しています。最初のバージョンは、個別のキーを持つローカルテーブルと依頼された業務フローに対応します。

## 次の取り込みを支える仕組み

| 機能 | 得られるもの |
| --- | --- |
| **識別を考慮したプロファイル** | キー候補、欠損、重複、先頭に0がある識別子の根拠。 |
| **結合の事前検査** | 結合前に不一致キーや行数が増幅する危険を確認。 |
| **3方向の照合** | 元データ・ローカル・新データを分離し、フィールドごとに競合を解決。 |
| **取り込みプレビュー** | 適用前に追加、更新、欠落、競合を確認。 |
| **業務インターフェース** | 検索、設定済みビュー、許可された編集、競合解決、履歴、CSV出力。 |
| **持ち運べるアプリソース** | 導入済みスキルから独立して動くPython/SQLiteアプリとローカル資産。 |

これらは判断のための根拠です。ファイル内で一意な列も、永続的な業務上の識別子とは限りません。結合が成功しただけでは、その合計が意図した意味を持つとは証明できません。

## 在庫ワークスペースを実行

**Python 3.10+**が必要です。CSV処理と生成したランタイムは標準ライブラリを使います。付属データは合成データです。

```bash
git clone https://github.com/hieunguyenak92/data-to-app.git
cd data-to-app
python3 skills/data-to-app/scripts/dta.py demo --out ./inventory-app
python3 inventory-app/app.py --port 8765
```

**http://127.0.0.1:8765**を開きます。商品を検索し、編集画面で許可されたフィールドを変更して出力してください。状態はワークスペース自身のSQLiteデータベースに保存され、再起動しても維持されます。

リポジトリのディレクトリで別のターミナルを開くと、次の商品スナップショットをプレビューできます。

```bash
python3 skills/data-to-app/scripts/dta.py import ./inventory-app --table products --file skills/data-to-app/assets/examples/inventory/next/products.csv
```

適用するには`--apply`を追加するか、アプリ内のプレビューと確認を使います。新ファイルでも変更されるフィールドをローカルで編集すると、競合解決を確認できます。

取り込みは**1テーブルの完全なスナップショット**です。含まれないレコードは欠落扱いで保持されます。一部だけのファイルを取り込むと、省略したレコードが欠落扱いになります。スキーマ変更や値が異なる重複キーは、変更前に拒否されます。

## 自分のファイルを使う

CSVはテキスト形式の表、XLSXはExcelブックです。XLSXには、ツールを実行するPython環境にオプションのリーダーが必要です。

```bash
python3 -m pip install openpyxl==3.1.5 defusedxml==0.7.1 et-xmlfile==2.0.0
```

入力上限は**1ファイル10 MiB、1テーブル50,000行、200列、1,000,000セル**です。XLSXは既定で最初のワークシートを使い、他のシートがあれば警告します。数式は再計算しません。

上のプロンプトで始めるか、ファイルを直接検査します。

```bash
python3 skills/data-to-app/scripts/dta.py inspect ./exports
```

エージェントはプロファイルを参考にモデルとワークスペースを構成します。技術的な手順は[英語の導入・CLI文書](docs/INSTALL.md)にあります。

## 出力、所有と範囲

CSVには、採用したローカル編集を含むアクティブなレコードの有効値を出力します。表計算ソフトで数式と解釈される危険を抑えるため、出力セルにアポストロフィが付くことがあります。内部の保存値は変わりません。欠落レコードはローカルに保持します。

生成サーバーは`127.0.0.1`にバインドし、ローカル資産を配信します。基本操作にホスティングサービスは不要です。構築中はAIホストのファイルアクセス・データ方針が適用されます。データベース、入力、出力には機密情報が含まれ得ます。[英語のプライバシー文書](docs/PRIVACY.md)を参照してください。

このリリースはローカルワークスペースであり、複数ユーザー認証やクラウド展開を保証しません。表計算の数式実行、あらゆる業務ルールの推論、任意のスキーマ移行、万能なデータ復旧には対応しません。重要な結果は実務に使う前に確認してください。
