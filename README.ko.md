# Data to App

### 파일은 소프트웨어가 됩니다. 다음 가져오기에도 당신의 결정은 남습니다.

**Claude 또는 Codex에 파일과 실제 업무를 맡기세요. 실행하고, 확인하고, 직접 소유할 수 있는 앱을 받으세요.**

Data to App은 CSV와 Excel을 원본을 추적하는 업무용 소프트웨어로 바꿉니다. 검색 가능한 레코드, 유용한 보기, 허용된 편집과 반복 가져오기를 제공합니다. 에이전트가 업무 흐름을 구성하고, 동작이 명확한 Python/SQLite 엔진이 원본·로컬 수정·새 스냅샷을 구분합니다. 완성된 앱, 소스와 로컬 데이터를 함께 받습니다.

> **다음 가져오기를 명확하게.** 원본 값은 `12`입니다. 사용자가 `20`으로 바꿉니다. 새 파일에는 `14`가 들어옵니다. Data to App은 로컬 값 `20`을 유지하고 원본·로컬·새 값의 충돌을 보여 주어 사용자가 결정하게 합니다. 같은 변경은 합쳐지고, 다른 결정은 계속 표시됩니다.

## 실제 업무로 시작하기

[스킬 설치](docs/INSTALL.md) 후 에이전트에 요청하세요.

> Data to App으로 `./exports`를 처리해 주세요. 재고 검색, 재주문 기준 미만 보기, 기준값과 메모 수정이 가능한 로컬 재고 도구를 만들어 주세요. 다음 파일을 가져올 때 수정 내용을 유지하고 판단이 필요한 변경을 보여 주세요. 앱을 실행하고 주요 동작을 확인해 주세요.

스킬은 파일 검사, 레코드 식별 기준과 작업 선택, 앱 생성과 실제 사용 확인으로 에이전트를 이끕니다. 사용자는 업무를 설명하고 에이전트가 기술 모델을 구성합니다. 키, 단위 또는 업무 규칙의 중요한 모호함에는 사용자의 명확한 답이 필요할 수 있습니다.

재고·주문 내보내기, 계속 수정하는 연락처 목록, 주기적인 파일로 전달되는 프로젝트·서비스 레코드에 적합합니다. 첫 버전은 개별 키가 있는 로컬 테이블과 요청된 업무 흐름에 집중합니다.

## 다음 가져오기를 위한 설계

| 기능 | 제공하는 가치 |
| --- | --- |
| **식별 기준을 고려한 프로파일링** | 후보 키, 누락값, 중복, 앞자리 0이 있는 식별자에 대한 근거를 제공합니다. |
| **조인 사전 검사** | 데이터를 결합하기 전에 일치하지 않는 키와 행 증식 위험을 확인합니다. |
| **3방향 조정** | 원본·로컬·새 값을 분리하고 필드 단위 충돌을 해결합니다. |
| **가져오기 미리보기** | 적용 전에 추가·갱신·누락 레코드와 충돌을 검토합니다. |
| **업무 인터페이스** | 검색, 설정된 보기, 허용된 편집, 충돌 해결, 이력과 CSV 내보내기를 제공합니다. |
| **이동 가능한 앱 소스** | 설치된 스킬과 독립적으로 실행되는 Python/SQLite 앱과 로컬 자산을 생성합니다. |

도구가 제공하는 것은 판단의 근거입니다. 파일에서 유일한 열이라고 해서 지속적인 업무 식별자임이 증명되지는 않습니다. 조인이 성공해도 합계가 의도한 의미와 일치하는지는 별도로 판단해야 합니다.

## 재고 워크스페이스 실행

**Python 3.10+**가 필요합니다. CSV 처리와 생성된 런타임은 표준 라이브러리를 사용합니다. 예제 데이터는 합성 데이터입니다.

```bash
git clone https://github.com/hieunguyenak92/data-to-app.git
cd data-to-app
python3 skills/data-to-app/scripts/dta.py demo --out ./inventory-app
python3 inventory-app/app.py --port 8765
```

**http://127.0.0.1:8765**를 여세요. 제품을 검색하고 편집기를 열어 허용된 필드를 수정한 다음 결과를 내보내세요. 상태는 워크스페이스의 SQLite 데이터베이스에 저장되며 앱을 다시 실행해도 유지됩니다.

저장소 디렉터리의 다른 터미널에서 다음 제품 스냅샷을 미리 볼 수 있습니다.

```bash
python3 skills/data-to-app/scripts/dta.py import ./inventory-app --table products --file skills/data-to-app/assets/examples/inventory/next/products.csv
```

적용하려면 `--apply`를 추가하거나 앱의 미리보기·확인 기능을 사용하세요. 새 파일에서도 바뀐 필드를 로컬에서 수정하면 충돌 해결을 확인할 수 있습니다.

가져오기는 **테이블 하나의 전체 스냅샷**입니다. 빠진 레코드는 누락으로 표시되고 보관됩니다. 일부 행만 담은 파일을 가져오면 나머지가 누락으로 표시됩니다. 스키마 변경과 값이 다른 중복 키는 데이터 변경 전에 거부됩니다.

## 내 파일 사용하기

CSV는 텍스트 테이블이고 XLSX는 Excel 통합 문서입니다. XLSX는 도구를 실행하는 Python 환경에 선택적 리더를 설치해야 합니다.

```bash
python3 -m pip install openpyxl==3.1.5 defusedxml==0.7.1 et-xmlfile==2.0.0
```

입력 제한은 **파일당 10 MiB, 테이블당 50,000행, 200열, 1,000,000셀**입니다. XLSX는 기본적으로 첫 워크시트를 사용하고 다른 시트가 있으면 알립니다. 수식을 다시 계산하지 않습니다.

위의 프롬프트로 시작하거나 파일을 직접 검사하세요.

```bash
python3 skills/data-to-app/scripts/dta.py inspect ./exports
```

에이전트는 프로파일을 참고해 모델과 워크스페이스를 구성합니다. 자세한 기술 절차는 [영문 설치·CLI 문서](docs/INSTALL.md)에 있습니다.

## 내보내기, 소유권과 범위

CSV 내보내기에는 수락된 로컬 수정을 포함한 활성 레코드의 유효값이 들어갑니다. 스프레드시트 수식 방어를 위해 위험한 내보내기 셀 앞에 작은따옴표가 붙을 수 있습니다. 내부 저장값은 바뀌지 않습니다. 누락 레코드는 로컬에 보관됩니다.

생성된 서버는 `127.0.0.1`에 바인딩하고 로컬 자산을 제공하며, 핵심 작업에 호스팅 서비스가 필요하지 않습니다. 앱을 만드는 동안 AI 호스트의 파일 접근·데이터 정책은 계속 적용됩니다. 데이터베이스, 입력과 내보내기에는 민감한 정보가 있을 수 있습니다. [영문 개인정보 문서](docs/PRIVACY.md)를 확인하세요.

현재 버전은 로컬 워크스페이스이며 다중 사용자 인증이나 클라우드 배포를 보장하지 않습니다. 스프레드시트 수식 실행, 모든 업무 규칙 추론, 임의 스키마 마이그레이션과 보편적 데이터 복구를 제공하지 않습니다. 중요한 결과는 실제 업무에 사용하기 전에 확인하세요.
